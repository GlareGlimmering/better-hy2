## v1.1.0-rc.7 候选版登录时序验收

在非特权本机隔离实例测试已校验 SHA256 的 RC.6 发布面板及 RC.7 候选面板。使用临时管理员和普通代理账号，每隔约 1.12 秒交替提交不存在的用户名和有效管理员的错误密码，各 24 次。两类响应体完全相同，均为 HTTP 200、应用码 50000。

| 版本 | 不存在的用户名中位数（ms） | 有效管理员密码错误中位数（ms） | 配对差中位数（ms） | 管理员组更慢的样本对数 |
| --- | ---: | ---: | ---: | ---: |
| RC.6 | 1.12 | 23.97 | +22.84 | 24/24 |
| RC.7 候选版 | 33.35 | 32.51 | −1.15 | 8/24 |

候选版拒绝伪造转发头的第 6、7 次请求（HTTP 429），可信反代登录返回 HTTP 200、应用码 20000。普通代理账号、改密前旧令牌、篡改令牌、签名有效的过期令牌和畸形令牌均返回 HTTP 200、应用码 50000。无令牌返回 HTTP 200、应用码 50401。公网链路未纳入本轮复测。

## v2.1.1-rc.1 SOCKS5 出站验收

- 面板配套内核为 v2.13.0-hui.6-dev，提交 dc6b01106be3ca86c21cf7a9695e858b8145671e。
- v2.1.0 现场报告：首次为一个账号设置出站时，另一个启用账号未绑定，保存因严格路由校验回滚。仅配置原生 SOCKS5 时，测试按钮受 Xray 服务状态限制而禁用。
- 自动化回归覆盖一次性绑定多个账号、拒绝遗漏或失效的节点、应用失败后的数据库绑定恢复，以及原生 SOCKS5 的测试按钮和接口权限。
- 待人工验收：在隔离 VPS 上保持 Xray 停止，测试已应用的 SOCKS5 节点，分开核对 TCP 与 UDP 结果。为未分配账号分别指定 SOCKS5 或 DIRECT，一次保存。新建 HY2 连接后核对实际出站。

## v2.1.1-rc.2 新建账户与出站绑定

- 现场反馈：新建 SOCKS5 账号在还有启用账号未分配出站时无法保存。关闭或删除账号后，新建抽屉可能沿用前一次表单信息。
- 候选版新建抽屉使用独立表单和新生成的连接密码。需要首次启用严格路由时，管理员在同一表单为已有未分配账号逐一指定出站。测试覆盖校验失败、应用失败后的回滚和使用同一份请求重试。配套内核继续使用 v2.13.0-hui.6-dev。
- 实机验收：先编辑再删除测试账号 A，打开新增并核对用户名、备注、密码、设备限制和出站的初始值。创建账号 B 并绑定 SOCKS5，同时明确选择所有未分配账号的出站。保存后核对账号与出站，再建立新的 HY2 客户端连接。

## v2.3.1-rc.2 配套升级与后续兼容性

- `hui update` 按内核哈希选择升级路径。已安装内核与目标配套的 SHA256 相同时，只换面板。哈希不同时，进入配套升级，停机后同时激活目标面板和内核。
- 停机前验证目标 Release 的 `HY2-PAIR.json`、双方制品 SHA256、架构和能力，识别源组合并准备可恢复快照。停机后保存最终一致的 SQLite 状态。启动后检查面板、HY2 及配置要求的协议和功能。失败时恢复旧面板、旧内核、数据库、配置和原服务状态。
- 以 [TRC 维护演练](https://github.com/GlareGlimmering/better-hy2/actions/runs/44899485257) 为实现基线。真实 systemd 已验证损坏制品在停机前拒绝、双制品切换成功、候选健康检查失败后的回滚，以及切换和回滚后的真实 HY2 流量。本批将这一流程接入常规更新。适用范围为有配套清单且正在运行的标准 v2 安装。旧 v2 更新器可通过目标版本安装器交接。v1.0.0 使用既有的显式迁移入口。
- 后续逐步把运行时的精确版本号门槛改为能力检查。先补齐严格用户出站与 Fail-Closed 的能力声明和回归，再用现有计量、限速和 Worker DNS-01 能力检查验证所需功能。发行时继续记录经过验证的默认配套内核及其 SHA256。

## v2.3.1-trc.2 DNS-01 权威传播验收

- 面板测试版配套 v2.14.0-hui.2-dev，内核提交 37c625faaacd68e835137695909cc1f4b84da9c5。Linux AMD64 制品以 Go 1.26.0 构建，SHA256 为 35eb09003de3026294f5f963474163d78600a3f12c546cbeab81dafe16f4baa9。
- 现场反馈显示 TXT 已在两台权威 DNS 上可查，两个递归解析器当时的 SOA 负缓存剩余 1491 秒和 337 秒。新内核用 IPv4 递归查询发现区域及权威 NS，并逐台直接验证本次挑战的 TXT 值。UDP 响应超时、截断或缺少权威标志时尝试 TCP。单次传播检查最多两分钟，DNS-01 签发准备总预算为四分钟。面板就绪等待六分半，保存及启动结果通过短请求轮询。
- 2026-11-21 人工实测。用该 Linux AMD64 内核，在 WSL 的空 ACME 目录及回环监听上配置 Worker 和 Let's Encrypt staging。确认 CA 颁发包含测试名称的 staging 证书，内核从开始 DNS-01 挑战到 QUIC 开始监听约 30 秒。随后直接查询两台权威 DNS，确认临时 TXT 已清理。首次试跑记录到 UDP 被中间网络接管，TCP 回退版本通过实测。
- 自动回归覆盖递归 TXT 负缓存、权威服务器返回另一订单的值、非权威 UDP 响应和 TCP 回退。
- 2026-11-21 SJC 操作者反馈，测试面板已成功取得证书信息。本条记录面板端的观察，SJC 客户端转发、TXT 清理及续期结果待单独确认。

## WireGuard 固定 UDP 中继 TRC

- 候选配套内核为 v2.14.0-hui.3-dev（0735b069e63acf79d1fe3e90e24ae87b23bd81c1）。面板要求内核报告 udpRelay: 1。
- 在「出站节点」添加 WireGuard UDP 中继，填写落地 IPv4:UDP 端口并保存。也可从新增账户的中继类型直接跳到「出站节点」。保存后在新增账户绑定该中继。节点列表可直接编辑和删除，已有账号绑定时可以修改落地端点，改名或删除前需先解除绑定。普通账号继续使用既有出站。启用严格绑定前，需要显式处理已有未绑定账号。
- 路由器 HY2 的 udpForwarding.remote 必须等于落地端点。私钥继续保存在 WireGuard 端点。实际 ImmortalWrt 跨 VPS 握手、HTTP 传输和落地断开后的隔离仍待人工验证。
